# VELA Architecture

VELA is a React single-page stargazing application backed by an ASP.NET Core Web API and SQL Server. The app combines an interactive map, astronomy lookups, light-pollution data, saved user locations, curated recommendations, star-party events, and several client-rendered visual astronomy experiences.

This document describes the current repository state.

## 1. System Overview

The project is split into three main runtime pieces:

```text
React/Vite SPA
  -> same-origin /api requests
  -> ASP.NET Core API
  -> SQL Server stored procedures

React/Vite SPA
  -> MapTiler raster/style URLs
  -> MapTiler CDN/API

ASP.NET Core API
  -> World_Atlas_2015.tif + GeoJSON assets
  -> rendered lightmap PNG tiles and sky data

ASP.NET Core API
  -> visibleplanets.dev
  -> proxied visible-planet JSON
```

Important current-state details:

- The frontend always calls backend endpoints through `/api`.
- In local dev, Vite proxies `/api` to `http://127.0.0.1:5152`.
- MapTiler base maps are built directly in the frontend by `src/utils/apiEndpoints.js`.
- The light-pollution overlay is not a MapTiler layer; it is generated by the backend as PNG tiles.
- Routing uses React Router hash routing, so direct hosting does not require server-side route rewrites.
- SQL access is stored-procedure based. There is no ORM.

## 4. Frontend Architecture

### 4.1 Entry and Bootstrap

`src/main.jsx`:

- imports global CSS
- registers `public/sw.js` on window load
- mounts `RouterProvider` inside `NotificationProvider`

`src/router.jsx`:

- defines a `createHashRouter` route tree
- runs `appBootstrapLoader`, which fetches recommendations and star-party events with `Promise.allSettled`
- handles login/register via the `/auth` route action
- guards hardware-heavy routes when hardware acceleration appears unavailable

### 4.5 Map Rendering

`MapViewport` owns the actual map tree:

- `MapContainer` sets Leaflet bounds, zoom limits, and base map configuration.
- In 2D mode, a `TileLayer` renders MapTiler raster tiles.
- If `lightOverlayEnabled` is true, a second `TileLayer` renders `/api/lightmap/{z}/{x}/{y}.png`.
- In 3D mode, `MapLibre3DLayer` replaces the Leaflet raster base layer.
- Markers include user location, placed marker, recommended spots, dark spots, favorites, and star-party events.

Base map URL flow:

```text
src/utils/apiEndpoints.js
  buildMapTilerRasterTemplateUrl(...)
    -> https://api.maptiler.com/maps/{mapId}/{z}/{x}/{y}.{format}?key=...

src/pages/Map/MapView/core/mapConfig.js
  MAP_TILES.dark/light/satellite.url

src/pages/Map/MapView/components/MapViewport.jsx
  <TileLayer url={MAP_TILES[mapType].url} />

Leaflet
  replaces {z}/{x}/{y}
  creates browser image requests
  positions returned images in the tile pane
```

Light overlay URL flow:

```text
src/utils/apiEndpoints.js
  getLightmapTileUrlTemplate()
    -> /api/lightmap/{z}/{x}/{y}.png

MapViewport
  <TileLayer url={LIGHT_TILE_URL} opacity={0.72} zIndex={5} />

Leaflet
  requests same-origin PNG tile images

Vite in dev
  proxies /api to the ASP.NET Core API
```

### 4.6 3D Map Mode

`src/pages/Map/MapView/components/layers/MapLibre3DLayer.jsx`:

- creates a MapLibre GL layer through `L.maplibreGL`
- uses the frontend MapTiler style URL from `buildMapTilerStyleUrl("streets-v2")`
- syncs MapLibre camera movement back into Leaflet
- disables some default MapLibre interactions
- adds custom mouse/touch pitch controls
- loads the MapLibre RTL text plugin once per browser session when available

### 4.7 Planets and AR Overlay

`usePlanets` fetches `/api/visible-planets?lat&lon` and stores the result for the selected map target.

`src/utils/planetUtils.js`:

- builds visible-planet API URLs
- caches responses in localStorage for 24 hours
- preloads planet texture assets

`src/pages/Map/PlanetPanel/` contains:

- desktop and mobile planet panel variants
- 3D planet cards
- planet info cards
- copy-to-clipboard helpers
- AR overlay

`PlanetArOverlay.jsx` uses:

- `navigator.mediaDevices.getUserMedia` for the camera feed
- `deviceorientation` events for heading/tilt guidance
- a portal target from `usePortalTarget`
- cleanup effects to stop camera tracks when the overlay unmounts

### 4.8 Discovery, Admin, and Visual Routes

## 5. Backend Architecture

### 5.1 Startup

`backend/src/Vela.Api/Program.cs` configures:

- controllers with string enum serialization
- Swagger in development
- JWT bearer auth
- authorization
- memory cache
- singleton `WorldAtlasService`
- typed `HttpClient` for `VisiblePlanetsService`

Middleware order:

1. Swagger in development
2. HTTPS redirection
3. permissive CORS
4. authentication
5. authorization
6. controller mapping

### 5.2 Controllers

| Controller | Route | Responsibility |
|---|---|---|
| `UsersController` | `/api/users` | register, login, current user, profile, admin user management |
| `FavoritesController` | `/api/favorites` | signed-in user favorites |
| `RecommendationsController` | `/api/recommendations` | public list and admin upsert/delete |
| `StarPartyEventsController` | `/api/star-party-events` | public events, admin event management, RSVP toggle |
| `SkyMapController` | `/api` | visible planets, sky quality, dark spots, lightmap tiles |

There is no current backend MapTiler controller. MapTiler URLs are generated by the frontend.

### 5.3 Business Logic Layer

The `BL/` classes are static facades:

- `BL.User`
  - registration/login normalization
  - password hashing and verification
  - JWT creation
  - token claim parsing
  - admin access guardrails

- `BL.Favorite`
  - favorite spot ID/default key generation
  - favorite custom-name normalization

- `BL.Recommendation`
  - recommendation ID generation and upsert/delete orchestration

- `BL.StarPartyEvent`
  - event normalization
  - stable event ID generation
  - status and RSVP orchestration

### 5.4 Data Access Layer

The `DAL/` layer uses ADO.NET and stored procedures through `DBService`.

| Service | Stored procedure family |
|---|---|
| `UserService` | users, profiles, admin management |
| `FavoriteService` | favorites |
| `RecommendationService` | recommendations |
| `StarPartyEventService` | events and RSVPs |

The backend does not use Entity Framework or migrations.

### 5.5 World Atlas Service

`WorldAtlasService` is responsible for:

- `/api/skyquality`
- `/api/darkspots`
- `/api/lightmap/{z}/{x}/{y}.png`

Supporting files live under `backend/src/Vela.Api/Application/WorldAtlas/`.

Sky quality:

```text
lat/lon
  -> AtlasMetadata.ToPixel()
  -> RasterSampler.TryGetFiniteArtificial()
  -> SQM/Bortle response
```

Dark-spot search:

```text
origin lat/lon + radius
  -> clipped raster scan window
  -> candidate sampling
  -> land/country filtering
  -> spacing/deduplication
  -> JSON response
```

Lightmap tile rendering:

```text
Leaflet requests /api/lightmap/{z}/{x}/{y}.png
  -> SkyMapController.GetLightmapTile()
  -> WorldAtlasService.GetLightTileAsync()
  -> TileBounds.FromXyz()
  -> RenderLightTile()
  -> ImageSharp 256x256 RGBA image
  -> PNG bytes
  -> image/png response
```

`RasterSampler` reads encoded TIFF tiles and caches TIFF tile arrays per sampler instance during a render/search operation.

### 5.6 Visible Planets Service

`VisiblePlanetsService`:

- builds upstream URLs from `VisiblePlanets:BaseUrl`
- calls `visibleplanets.dev`
- returns upstream JSON/content-type data
- uses `IMemoryCache` for short-lived response caching

## 6. Database Architecture

Tables:

| Table | Purpose |
|---|---|
| `Users` | auth identity, profile, role/admin data |
| `Favorites` | saved coordinates per user |
| `Recommendations` | curated stargazing locations |
| `StarPartyEvents` | event metadata |
| `StarPartyEventRsvps` | event/user RSVP rows |

Relationships:

- `Favorites.UserId -> Users.Id`
- `StarPartyEvents.HostUserId -> Users.Id`
- `StarPartyEventRsvps.EventId -> StarPartyEvents.Id`
- `StarPartyEventRsvps.UserId -> Users.Id`

Manual setup order:

1. `Tables/Users.sql`
2. `Tables/Favorites.sql`
3. `Tables/Recommendations.sql`
4. `Tables/StarPartyEvents.sql`
5. `SP/User SPs.sql`
6. `SP/Favorite SPs.sql`
7. `SP/Recommendation SPs.sql`
8. `SP/StarParty SPs.sql`
9. optional `Seed/InitialContent.sql`

Some SQL columns intentionally store JSON text:

- recommendation photo URLs
- recommendation source URLs
- star-party host checklist
- star-party RSVP projection payloads returned by procedures

## 9. Caching

Frontend:

- service worker caches matching external tile-host requests
- visible-planet responses are cached in localStorage for 24 hours
- settings/session/map type are persisted in localStorage

Service worker:

- cache name: `vela-map-tiles-v4`
- metadata cache: `vela-map-tiles-meta-v2`
- max age: 30 days
- max entries: 4000
- matching hosts include `api.maptiler.com`, `basemaps.cartocdn.com`, `tile.openstreetmap.org`, and `tiles.stadiamaps.com`

Backend:

- memory cache is registered globally
- `VisiblePlanetsService` uses memory caching
- World Atlas metadata and GeoJSON geometry are loaded lazily

## 11. Operational Notes

- The project currently exposes a MapTiler key in frontend code. Treat it as a public/browser key unless the architecture is changed to a backend proxy.
- The World Atlas TIFF is required for sky quality, dark spots, and lightmap tiles.
- The API has no automatic database migration path.
- Hardware acceleration is required for the heavier visual routes.
- The home map can still operate in 2D Leaflet mode without WebGL.
- Camera AR mode needs a secure browser context, so mobile testing should use HTTPS through a tunnel or deployment.
- The backend BL/DAL pattern is intentionally simple, but static BL facades and direct DAL construction make dependency injection/testing less flexible.
